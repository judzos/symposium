LSTM

Long Short-Term Memory is a recurrent architecture whose repeating module uses a cell state and learned gates. Hochreiter and Schmidhuber introduced it (1997). Designed to reduce the long-term-dependency difficulty of plain recurrent networks, it became a widely used sequence model before attention-based architectures.

  FG --> AD[Input gate, with a tanh proposing candidates — what to add]
  AD --> C2[Cell state — a belt of minor linear interactions only]
  C2 --> OG[Output gate — how much of the state to expose]
  OG --> H[Hidden output for this step]

In short

  • The cell state is a conveyor belt of minor linear interactions, so information persists along it unless a gate changes it.
  • Forget, input, and output gates are sigmoid-scaled multiplies that decide what to drop, what to add, and what to expose.
  • Large comparisons found the popular variants about the same, pointing to cell state plus gating as the source of performance.
  • Trained on raw characters, LSTMs produced plausible text and code, with roughly 5% of cells learning legible features.
  • Sequential steps limit parallelism, a central reason the Transformer displaced it in many large models, though LSTMs remain useful.

The cell state is the idea

The cell state is a conveyor belt running the length of the chain, subject only to minor linear interactions1. Information flows along it unchanged unless a gate changes it. Everything else in the LSTM is machinery for deciding what changes.

This inverts the vanilla RNN’s practical tendency: the cell state supplies a path along which information can persist unless a gate changes it. Gate values, training, finite precision, and recurrent depth still prevent a guarantee of perfect memory, but this path makes long retention easier to learn.

What default does the cell state invert, relative to a vanilla RNN?

In a plain RNN information decays unless actively preserved; along the cell state it persists unless actively forgotten. Remembering becomes the default rather than the thing the network has to learn.

Why does the cell state only take linear interactions?

Because repeated non-linear transformation is what destroys information across many steps. Keeping the belt to minor linear operations is what lets a signal travel the length of the chain intact.

Three gates

A gate is a sigmoid layer followed by a pointwise multiply. The sigmoid emits a value in [0, 1] per component: 0 lets nothing through, while 1 lets everything through.

  1. Forget gate — what to drop from the cell state.
  2. Input gate (with a tanh layer proposing candidate values) — what to add.
  3. Output gate — what portion of the cell state to expose as this step’s output.

One running example carries all three: a language model holding the grammatical gender of the current subject so it can pick the right pronoun, dropping it when a new subject appears, and outputting singular/plural in case a verb comes next.

Why is a gate a sigmoid followed by a pointwise multiply?

The sigmoid emits a value in [0, 1] per component, and multiplying by it scales that component between “let nothing through” and “let everything through” — so the gate is a learned, per-component, continuous filter rather than a switch.

What distinguishes the output gate's job from the forget and input gates'?

Forget and input edit the cell state itself; the output gate decides only how much of that state is exposed as this step’s output. The network can hold something it is not currently using.

The one-line version

VIP Cheatsheet: Deep Learning2 compresses all of the above into one sentence, that an LSTM is an RNN that avoids the vanishing gradient problem by adding “forget” gates, plus a table naming each gate by the question it answers: input (“write to cell or not?”), forget (“erase a cell or not?”), output (“reveal a cell or not?”), and the gate proper (“how much writing?”). Beside Olah’s essay, it shows how pacing can serve different purposes while teaching the same content.

The variants are a footnote

Peephole connections let the gates see the cell state. Coupled forget/input gates decide together. The GRU merges forget and input into one update gate and merges cell state with hidden state, making the result simpler. Greff et al. (2015) compared the popular variants and found them about the same; Jozefowicz et al. (2015) searched over ten thousand architectures. These comparisons point to the cell-state-plus-gating idea, rather than any particular arrangement, as the source of their performance.

What do the LSTM variant comparisons establish?

That no particular gate arrangement matters much — the popular variants perform about the same across large comparisons and searches. The work is being done by the cell-state-plus-gating idea itself.

What it could do

The empirical half comes from experiments that all use an LSTM3. Trained on raw characters, it produces plausible Shakespeare, valid markdown, syntactically coherent C, and LaTeX. Visualising individual cells reveals one that switches on inside a URL, one that tracks position within a [[ ]] scope, and one that counts through “www”. Roughly 5% of cells learn something legible without anyone specifying those features.

What is the significance of a single cell that switches on inside a URL?

The structure was never specified — the model was trained on raw characters. It shows that interpretable, discrete features emerge from character prediction alone, in roughly 5% of cells.

Why it stopped being the default for many large models

Parallelism was a central reason. An LSTM must process step t before step t+1, which limits parallel execution across sequence positions; the Transformer removed that recurrent dependency during training. Accuracy, scaling behaviour, and task fit also influenced the shift, and LSTMs remain useful where their recurrence and state fit the task. Olah’s 2015 conclusion identified attention as the next architectural step.

What ended the LSTM's dominance, and what did not?

A central factor was parallelism: recurrent step t precedes t+1, while transformer training can process positions in parallel. Accuracy, scaling, and task fit also contributed, and LSTMs were not eliminated.
